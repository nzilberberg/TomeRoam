## What was checked, and how it came out

**F1 — the source-text-mutation verification path is genuine, not a rubber stamp.** The prior review's Critical
was that the CI sweep reported source-text mutation #79 UNCAUGHT (exit 1) because its only catcher,
`home-layer-invariant.test.js`, is excluded from `behaviourTests()` and no behavioural test sees a CSS change.
The fix adds `caughtBy: 'home-layer-invariant.test.js'` to #79 and a `gateTestsFor(m)` helper: a mutation carrying
`caughtBy` has the sweep run *that named gate* against the mutated source, else it runs the behavioural set.

The mechanism is a **real catch**, executed this pass:
- `node tools/mutation-sweep.mjs 79` → `#79 caught (2 failing) via source-text gate home-layer-invariant.test.js`,
  exit 0. The sweep applies #79 (writes `#home { transform: none }` to `css/app.css` on disk), then runs
  `home-layer-invariant.test.js`, which reads the mutated file — PROMO.base + PROMO.cascade redden (2 failures),
  and those 2 failures are what the sweep counts as the catch.
- **Non-vacuous.** `node --test test/home-layer-invariant.test.js` on the un-mutated working tree → 4/4 pass. So
  the gate is green at baseline and reddens *only* under the mutation; the "caught" verdict is strictly
  conditioned on real reddening. The counting branch is unchanged: `failures === 0 → UNCAUGHT` — the very branch
  that flagged #79 before this fix. A `caughtBy` gate that failed to redden would still report UNCAUGHT. There is
  no path by which #79 reports caught without the gate actually failing.
- **General, not a #79 special-case.** `gateTestsFor` branches on `mutation.caughtBy` (a property), with no
  literal '79' or 'home-layer-invariant' in the logic. Any future source-text-only mutation that names its own
  gate is verified the same way.
- **No `benignAlone`.** Confirmed — the fix uses the positive path I required, not the false-survivable escape
  hatch I warned against.
- **No residue.** The loop is unchanged apart from *which* tests run: apply → run gate → `restore()`. Tree
  confirmed clean after each sweep invocation.

## Note (not a finding)

The `caughtBy` mechanism trusts the author to name a gate that is (a) in `SOURCE_TEXT_GATES` and (b) green at
baseline, so its red-under-mutation is attributable to the mutation. For #79 both hold and are verified. This is
the same green-baseline assumption the whole behavioural sweep already rests on, so it needs no new guard here; a
future hardening could assert `caughtBy ∈ SOURCE_TEXT_GATES`, but its absence is not a defect in this change.
