## 3. The design — the `#browse` fixed own-scroll recipe (NO `will-change`)

**One line:** active `#browse` becomes a `position:fixed` + `overflow-y:auto` own-scroll box (inset between the fixed topbar and navbar, NO `will-change`, NO transform), so it never drives the document height and `window.scrollY` is always 0 **on the signed-in app views (home/browse)**. Its visible `.browsepage` scrolls inside it; the fixed `.alphaindex` strip stays viewport-anchored because plain `position:fixed`+`overflow` does not establish a containing block for a `fixed` descendant (Linnaeus Q1).

**Scope of the "window.scrollY ≡ 0" invariant (F3).** The constant-0 window scroll holds for the SIGNED-IN app views (`#home`/`#browse`, both fixed own-scroll). `#signin` is a separate in-flow pre-app state OUTSIDE the swipe flow and outside this plan's surface — it is not a swipe source/destination and none of the re-homed consumers run against it. The invariant is scoped to the signed-in app, not asserted for the sign-in screen.

**The recipe (mirrors `#home` css:123-133, MINUS the `will-change` line — the load-bearing difference).** Recommendation (U11 — grounded by Linnaeus; the inset invariants mirror `#home`, the NO-`will-change` is a hard invariant, not a preference):
```css
#browse {
  position: fixed; left: 0; right: 0;
  top: calc(var(--safe-top) + 51px);            /* below the fixed .topbar */
  bottom: calc(var(--nav-h) + var(--nav-pad));  /* top of the nav bar (no transport) */
  /* z-index: OMITTED — plain position:fixed does NOT create a stacking context, so
     the fixed .alphaindex (z24) keeps participating in the ROOT stacking context
     exactly as today (unpositioned #browse). #home (z20) still paints above #browse.
     A z-index here would clamp .alphaindex into #browse's context — verify on device,
     R-strip. */
  max-width: 640px; margin: 0 auto; padding: 14px 16px 40px;
  overflow-y: auto; -webkit-overflow-scrolling: touch; overscroll-behavior: contain;
  background: var(--page-bg);   /* references css:41 — does NOT alter it */
  /* NO will-change / NO transform — Linnaeus Q1: either would establish a containing
     block for the fixed .alphaindex and reproduce the .195/.196 strip break. */
}
body.has-player #browse { bottom: calc(var(--nav-h) + var(--nav-pad) + 106px); padding-bottom: 20px; }
```

**Why the strip survives (Linnaeus Q1, load-bearing).** `.alphaindex` is `position:fixed` (css:638), built per-page into `.browsepage` (browse.js:434-436,643,670). A `fixed` descendant's containing block is the viewport UNLESS an ancestor carries a non-`none` transform / `will-change` naming one / filter / perspective / contain / container-type. Plain `position:fixed` and `overflow-y:auto` on `#browse` establish NEITHER → the strip stays viewport-anchored and un-clipped. The `.195/.196` dead-end that broke it was a PERMANENT transform/`will-change` on `#browse`, not the overflow. **The recipe MUST NOT copy `#home`'s css:131 `will-change:transform`** (harmless on `#home`, which has no fixed descendant; fatal on `#browse`). Verify no transform/`will-change` LEAKS onto `#browse` from any parking/animation rule (the mid-drag mover transform is transient and desired — it re-parents the strip to ride the slide, then clears at finalize, exactly as today; §9).

**Stacking / clip (grounded, device-checkable).** With `#browse` `position:fixed` and NO z-index, it does not create a stacking context; `.alphaindex` (z24) stays in the root context and `#home` (z20) still paints above `#browse` — but `#browse` and un-transformed active `#home` are never both visible (Nav.setView display:none's the inactive one), so no conflict. During a browse→browse swipe the incoming real `#browse` is a fixed transformed mover (translateX) — the SAME pattern 6i proved for `#home`-as-incoming-mover; the transient transform re-parents `.alphaindex` to ride the slide, clearing at finalize. This in-flow-clipped → fixed-mover change is device-owed (R-browse2browse). Update the css:118-119 comment ("above the unpositioned #browse") on scrub.

**What this buys (the confirmed fix, made permanent).** With BOTH in-flow views fixed, the document height is ALWAYS just the `.app` css:73 runway (`viewport + 12vh`), whether home or browse shows. Hiding `#browse` on `→home` no longer collapses the document → nothing to clamp → `window.scrollY` never jumps → the Books→Home scroll-clamp flash (subsystem §22 flash A / the probe's target) is removed BY CONSTRUCTION (§7). The `.266` pin — which achieved the same by pinning the document tall per-transition — is no longer needed and is retired.

## 4. Ordering and atomicity (required by boundary_relocation)

Pin the INVARIANT, not the line (EC §4.7, U8). Each is PRESERVED, with its target re-homed:

- **O1 — abort restore: render-before-scroll.** On a browse→browse abort (`finPlan.abortRender === 'rerender'`), the source page must be RE-RENDERED into `#browse` (`applyScreen(dest,{render:true})`, app.js:1201) BEFORE the source scroll is restored — a `scrollTop` write needs the content present to have `scrollHeight`. Re-home: the restore target moves from `window.scrollTo(0,cur.scroll0)` (app.js:1203) to `#browse.scrollTop = cur.srcScroll`, still AFTER the re-render. `@order`: applyScreen render → then set `#browse.scrollTop`.
- **O2 — page entry: build/show-before-position, then realize.** On `positionOnEnter` the page is built/shown, THEN `applyScrollY` writes the scroll, THEN `_realize` runs (browse.js:230-233). Re-home: `applyScrollY` writes `#browse.scrollTop` (not `window.scrollTo`); the realize-after-write order is unchanged. `@order`: show page → set `#browse.scrollTop` → realize.
- **O3 — `→home`: deactivate-before-hide (UNCHANGED, still required).** `browseWillHide()`/`Browse.deactivate()` captures the virtual controller's anchor from REAL geometry BEFORE `#browse` gets `.hidden`/display:none (nav.js:61-67) — a hidden box measures zero. This ordering STAYS; only the probe pin that followed it (nav.js:84) is removed. `@order`: deactivate → then hide `#browse`.
- **O4 — gesture realize freeze.** The virtual-list realize is FROZEN during a live gesture (`setScrollSuspended(true)` at `beginHold`, one settled realize at `endHold`, browse.js:146-171). Scroll-source-agnostic — the freeze mechanism is unchanged; the one settled realize now computes against `#browse.scrollTop`. `@order`: freeze at beginHold → one realize at endHold against the settled `#browse.scrollTop`.

Atomicity: **S1 (the fixed `#browse` recipe) + S2 (the six-consumer re-home) + S3 (the swipe.js:281 browse `ghostY` branch → `#browse.scrollTop` AND the `.alphaindex` clone exclude) must ship in ONE commit.** A fixed `#browse` with window-based consumers leaves browse scrolling dead (realize never fires, restore writes the wrong surface); and S1 WITHOUT S3 makes every outgoing browse ghost read `window.scrollY` = 0 → the ghost renders the list at the TOP (6i's own jump-to-top Loki case) PLUS a strip mispositioned by the transform — a VISIBLE regression on every browse→browse and browse→overlay swipe. So an interim S1+S2 (without S3) is not shippable. This is one atomic boundary (§14). S4 (retire the `.266` pin) and S5 (the PolicyLedger entry) MAY be follow-ups — the pin is a benign redundant no-op under a fixed `#browse` (it pins a document that no longer collapses), and the ledger entry is a records reconciliation.

## 5. Runtime-dependency policy (required by boundary_relocation)

Each re-homed consumer accesses `#browse` through its EXISTING injected/local handle — no new ambient global lookup (EC §4.3, U9):
- **Browse (B2/B3/B4):** via `o.mount`, which IS `#browse` (injected at `Browse.init`, app.js:2856 `mount: $('browse')`). No `document.getElementById`.
- **VirtualList (B1):** the scroller is INJECTED, not hardcoded — browse.js passes a `scrollHost` accessor (returning `o.mount` = `#browse`) into `createController`; the module stays generic (it must not name `#browse`). The single static scroll listener moves to capture-phase `document` (catches `#browse`'s non-bubbling scroll generically, mirroring `scrollbar.js:95`); the active controller filters by `isVisible()` + its own `getBoundingClientRect` (§6 B1).
- **ScrollBar (B5):** already capture-phase on `document` (scrollbar.js:95); `surfaceKind`/`metrics` read the event `target` element's `scrollTop` — the element arrives via the event, no ambient lookup.
- **Swipe.ghostApp (B6/§9):** reads `#browse` via `env.document` (`doc.getElementById('browse')`), IDENTICAL to the existing home branch `doc.getElementById('home')` (swipe.js:281) — the module stays DOM-free at load, drivable against a fake env.
- **app.js start()/finalize (B6):** via `$('browse')` (`byId`), the existing handle.
No module reads `#browse` at module-load time; every access is per-gesture/per-scroll through an injected or event-delivered handle. Module/top-level evaluation stays DOM-free.
