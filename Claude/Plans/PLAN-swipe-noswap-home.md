## 3. The design — fixed own-scroll `#home` slide-and-leave

**One line:** active `#home` never leaves `position:fixed`. Parked `#home` is already `position:fixed; transform: translateX(-101vw)` (css:103-107). Active `#home` becomes `position:fixed` too — an `overflow-y:auto` own-scroll box (sized to dynamic content, correction 1) sitting INSIDE the retained tall-document runway that seats the fixed bars (§8, A2) — and the transition into home slides the real fixed `#home` from its off-screen `translateX` to `translateX(0)` and LEAVES it.

**The flash has TWO competing underived hypotheses; the design provably removes ONE (F3).** Linnaeus carries two [UD] hypotheses for the camera-confirmed carousel raster-from-empty, NEITHER confirmed: **(i)** the `#browse`-leaving-flow document collapse REPOSITIONS the carousel scroll-boxes to a new viewport y and their layers re-raster (`PROBE-home-carousel` §5, marked [UD]); **(ii)** clearing `#home`'s parked `translateX(-101vw)` on its `will-change:transform` layer forces the descendant carousel scroll-layers to re-raster from empty (`PROBE-swap-necessity` §5/§6 item 1, marked [UD]). This design targets both surfaces but PROVABLY removes only (i):
- **No home-snapshot.** Constraint E (two in-flow views cannot coexist, §2.1) DISSOLVES: a fixed `#home` is not an in-flow view sharing the document scroll, so it coexists with the in-flow `#browse` directly — exactly as parked `#home` already coexists with active `#browse` today.
- **No occlude-then-uncover.** The incoming mover IS the real `#home`, on-screen and rastering throughout the slide — never behind a cover; the camera pinned the flash to the cover-drop uncover of the occluded real carousels, and there is no such uncover here.
- **Hypothesis (i) removed (provable from source).** `#browse` leaving flow still collapses the DOCUMENT height, but a fixed `#home` is laid out against the viewport, so its carousels DO NOT reposition on the collapse; the document scroll clamp is on the document, which the fixed `#home` ignores.
- **Hypothesis (ii) SURVIVES the design and IS R1(a).** The real `#home` still slides from its parked `translateX(-101vw)` (via un-park + an inline mover transform) to `translateX(0)` — the same transform-clear on the same `will-change` layer whose descendants are the carousels. **So this design does NOT by itself guarantee the flash is gone; it is device-gated on R1(a).** If R1(a) reddens, the in-scope, buildable fix is R1(a)'s wrapper/ancestor slide (transform a wrapper so `#home`'s own layer is never mutated) — the mechanism-(ii) mitigation. The flash is NOT claimed fixed until R1(a) is device-clean (§11).

**Choreography (`browse→home` commit):**
1. `buildConstruction` builds the outgoing app-ghost of `#browse` (snapshot at the current scroll, opaque `ghostWrap`) — the invisible real→ghost swap, as 6f/browse→browse already do.
2. The incoming resolves to the real `#home`, un-parked to its ACTIVE fixed state (remove `.parked`; `#home` stays `position:fixed`, now inset/own-scroll rather than off-screen) with an inline mover transform `translateX(off)`. `#browse` leaves document flow (its ghost covers it). No reflow of `#home` — it was fixed parked, it is fixed active.
3. Drag: the outgoing ghost slides out, the real fixed `#home` slides in (filmstrip), carousels rastering on-screen the whole time.
4. Commit/finalize: the mover transform clears (app.js:775) → fixed `#home` rests at `translateX(0)`; the outgoing ghost drops OFF-SCREEN (`dropPanes`, invisible); `applyScreen(home,{render:false})` reconciles — NO hold, NO cover-drop.

`overlay→home` is identical on the incoming side (real fixed `#home` slid in); its outgoing stays `real-source` (an overlay is additive/own-scroll and does not hold the document height).

**Abort (`browse→home`):** takes the no-hold finalize path (F7) — `browse→home` has `finalizationPlanFor.abortRender === 'none'` (`'rerender'` is `browse→browse`-only, swipe.js:174), so the abort goes through app.js:1238-1257: `dropPanes()` + `applyScreen(dest=browse, {render:false, resetScroll:false})` + `window.scrollTo(0, cur.scroll0)`. `abortRender:'none'` is the correct decision (I7, §7 recovery), NOT the `browse→browse` rerender-hold branch (app.js:1228-1236). **No re-decode of `#browse` covers on the return rests on the browse-page PARK mechanism** (Loki note #3): during the swipe `#browse`'s page node is PARKED — off-viewport but STILL PAINTED (`.browsepage.parked`, css:83-96) — so on abort it un-parks with covers warm; "nothing was rendered into it" (`renderDestination` is `home-host`, not `browse-host`) is necessary but the painted-park is what keeps the covers decoded. The fixed `#home` is re-parked (transform back to `translateX(-101vw)` — trivial, no reflow). **The abort has NO second uncover-jump once L5 lands** (§9): with the outgoing ghost faithful to `#home.scrollTop`, the ghost and the re-appearing real `#home` show the same scroll position, so there is no jump at the ghost drop.

- **CREATE / acquire.** Active `#home` ACQUIRES an own vertical scroll container: `position:fixed` + `overflow-y:auto` + `-webkit-overflow-scrolling:touch`, inset between the fixed bars, sized to dynamic content (correction 1). Created by the CSS rule change on `#home` (the base rule gains the active-fixed geometry; `#home.parked` already carries `position:fixed`). Its scroll position is reset to top on home entry (`#home.scrollTop = 0`, replacing the document `scrollTo(0,1)`).
- **BORROW.** The real `#home` element is BORROWED as the incoming mover (ownership `borrowed-real`, not the prior `owned-pane` snapshot) — it receives a temporary inline transform during the drag and is NEVER removed (borrowed-real teardown clears the transform, app.js:775; EC §4.4). The `window` object is no longer borrowed for a `→home` `scrollend` listener (that listener is deleted, §7).
- **MUTATE across the drag.** The only mutation on the borrowed `#home` is the inline `translateX` mover transform (start→settle→cleared at finalize) and the `.parked` class removal (at start) / re-addition (on abort). Its `scrollTop` is owned by `#home` itself thereafter.
- **RELEASE.** At finalize, the mover transform is cleared (app.js:775) → `#home` rests fixed at `translateX(0)`; the OUTGOING app-ghost (owned-pane) is released off-screen via `dropPanes`. - **DISPOSE / destroy.** The DELETED `→home` hold resources leave the session-owned set: `cur.revealScrollEnd`, `cur.revealSettleTimer`, and the `settled`/`scrollSettle` plumbing (app.js:823-824,833,908-915) are removed; `holdGhostUntilPaintable` keeps only the `abort→browse` decode+paint path. - **FAILURE / error.** If the fixed `#home` fails to un-park (a thrown `home-host` render), the outgoing ghost is disposed by the existing `disposeOwnedPanes(session,'superseded')` / orphan sweep (subsystem §14) and the source is restored (phase-aware recovery, EC §4.17); no new error path is introduced.
